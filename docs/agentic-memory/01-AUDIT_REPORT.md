## 2. Findings that change the plan (verified on `4778059`)

1. **No recovery from a provider context-overflow error.** `grep` over the whole crate finds no handling for `context_length_exceeded` / "prompt is too long" / "maximum context length". The loop (`agent_loop.rs` ~L700, `call_with_routing(...).await?`) returns the error and the turn fails. The pre-call budget is an estimate (calibrated, but the first call of a model and non-OpenAI tokenizers are estimates), so a wrong estimate kills the turn instead of compacting and retrying. Spec §8.4 step 12 ("retry with the compacted context") is missing. **Highest risk.**
2. **Context observability is post-hoc and aggregate only.** `context.usage` (~L788) is emitted after the response with one estimated total; `context.limit_resolved` gives the budget. There is no per-source breakdown (system, tools, memory, recent turns, tool results), no record of *why* the memory block entered the context, and nothing is emitted for a call that fails. Spec §4.7 is partially met.
3. **Retrieval depends entirely on the model-written segment index.** `turn_memory.rs::select_segments` (~L1290) picks turns by matching the question against segment topics/summaries; with no match it falls back to the first `MAX_RECALL_TURNS` (40) turns and marks the rest NOT READ. A detail that the summarizer did not put into the index (an exact error string, a number, a name mentioned once) cannot be located in a long chat. There is no full-text index over the original turns. (FTS5 is already used elsewhere: `doc_index.rs` indexes workspace documents in `document_chunks` with `tokenize = 'unicode61'`, so the bundled SQLite has FTS5; chat turns were never indexed.) Spec §7.2 asks to evaluate SQLite FTS before vectors.
4. **Default FTS5 tokenizer fragments Bengali** (this also affects the existing `doc_index.rs` document search; logged, not changed here because documents are outside conversation memory). Measured with SQLite 3.x (`python3 sqlite3`, `fts5vocab`): `unicode61` splits "প্রকল্পের নাম কাগজের নৌকা" into `প, রকল, পর, ন, ম, ক, গজ, র, ন, ক` because vowel signs/virama (Unicode Mc/Mn) are separators; `কাগজ` then also matches unrelated words. With `tokenize="unicode61 categories 'L* N* Co Mc Mn'"` the terms are `প্রকল্পের, নাম, কাগজের, নৌকা`, and prefix queries (`কাগজ*`) match inflected forms. The design uses the latter.
5. **`grep_files` truncates to the first 50 matches with no way to continue** (`tool_runner.rs` `MAX_GREP_MATCHES`, `grep_file` ~L1322: `truncated: true` and nothing else). Spec §8.5 forbids arbitrary first-N truncation for grep. (`read_file` already pages; shell/web_fetch keep originals by result ID.) `glob`/list (`MAX_MATCHES` 100) has the same shape but is a listing, not a result body; left as is and logged.
6. **Agent can only reach memory through `recall_turns`.** No read-only inspection of current/superseded decisions, versions, segments or the context budget is reachable by the loop. Spec §9.2 lists these as *potential*; adding a single read-only `memory_inspect` tool is the smallest safe step. Write tools (update/supersede/revert/request_compaction) are deliberately not exposed to the model (see architecture ADR-A5).
7. **Web search results are provider-side** (`llm_driver.rs` ~L320 server tool `web_search`, `WebSearchToolResult`): the app never holds the full body, so chunking does not apply; logged as a limitation.
8. **Memory UI** lacks version comparison (spec §11 item 4) and any view of context assembly / overflow events (items 11–13 partially: jobs and failures exist, last successful compaction time does not).
9. **Sub-agent scoping is correct by construction**: children run under their own session key; `recall_available` checks memory of that session only; parent memory is not injected. Verified in source; a cross-session isolation test for retrieval is added in this branch (see test report).
10. **Known out-of-scope bug**: `subagents.rs::set_settings` (~L720) resets all sub-agent settings on one bad key. Not memory-related; not changed here.
