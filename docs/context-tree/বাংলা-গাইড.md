# কনটেক্সট ট্রি — বাংলা গাইড

এই ডকুমেন্টটা কোড ছাড়া বোঝার জন্য: কী বানানো হয়েছে, কীভাবে কাজ করে, কীভাবে চালু
করবেন, কীভাবে যাচাই করবেন, আর কী কী এখনো বাকি। কোডের ভেতরের মন্তব্য ইংরেজিতেই থাকে
(যাতে ভবিষ্যতে যে কেউ কোড পড়ে তার অসুবিধা না হয়) — ব্যাখ্যা সবই এখানে বাংলায়।

---

## ১. এক নজরে

মডেলের কনটেক্সট উইন্ডো সীমিত। আগে ইঞ্জিন নিজেই ঠিক করত কোন টার্ন/ফলাফল/ফাইল যাবে আর
কোনটা যাবে না — মডেল জানত না উইন্ডোতে কী আছে, কত জায়গা বাকি, বা কী বাদ পড়ছে। এই
ফিচার মডেলকে তিনটা জিনিস দেয়:

1. **দেখা** — প্রতি রিকোয়েস্টে একটা চেকলিস্ট: কোন আইটেম ভেতরে (●), কোনটা বাইরে (○),
   কোনটা শুধু নোট (◐), কোনটা সামারিতে বদলানো (✦), কোনটা লক করা (⚿), আর প্রতিটার
   টোকেন খরচ।
2. **নিয়ন্ত্রণ** — একটা টুল, `ctx`; দিয়ে মডেল নিজে সিদ্ধান্ত নিতে পারে কী ভেতরে থাকবে।
3. **নিরাপত্তা** — উইন্ডো টাইট হলে ইঞ্জিন নিজে থেকে সবচেয়ে কম-দামি জিনিস সরায়, আর
   **কেন সরাল** সেটা লগে লেখে।

তিনটা জিনিস কখনো মডেলের হাতের বাইরে:

| | মানে |
|---|---|
| **আইন** | `sys/core` (রুলস প্রম্পট) — কখনো বাদ যায় না, কেউ বদলাতে পারে না |
| **সত্য** | `turn_archive`, `tool_results`, ইঞ্জিনের সামারি — কনটেক্সট অ্যাকশন এগুলো **লেখে না**, শুধু ঠিক করে *কী পাঠানো হবে* |
| **প্রমাণ** | প্রতিটা নোড তার উৎসের ঠিকানা রাখে (turn নম্বর, result id, ফাইল পাথ), তাই যা বাদ পড়ে তা পরে ফেরানো যায় |

**সবকিছু উল্টানো যায়।** কিছু বাদ পড়া মানে ডিলিট নয় — শুধু ওই রিকোয়েস্টে পাঠানো হচ্ছে না।

## ২. কীভাবে চালু করবেন

ফিচারটা **ডিফল্টে বন্ধ**। `main`-এ মার্জ করলেও আচরণ বদলাবে না। চালু করতে ডেটাবেসে
একটা সারি:

```sql
-- সেশন ডেটাবেসে (ctx_meta টেবিল নিজে থেকেই তৈরি হয়)
INSERT INTO ctx_meta (key, value) VALUES ('enabled', '1')
ON CONFLICT(key) DO UPDATE SET value = '1';
```

কোড থেকে করলে: `context_tree::wiring::set_enabled(db_path, true)`।

**সেটিংস স্ক্রিন/প্যানেল থেকে** (নতুন): অ্যাপ থেকে `action: "ctx.settings"` পাঠান —
ব্রিজের চ্যানেলটা `memory.*` অ্যাকশনের মতোই, আলাদা কোনো bridge মেথড লাগে না।

```jsonc
// পড়া — কোনো settings ছাড়া
{"action": "ctx.settings"}
// → {"settings": {"enabled": false, "thresholdPercent": 70, "summaryTokens": 600,
//                 "tempKeepSecs": 0, "standbyTtlSecs": 86400, "renderInChat": false}}

// লেখা — শুধু যা বদলাতে চান
{"action": "ctx.settings", "settings": {"enabled": true, "threshold_percent": 60}}
// → {"settings": {...}, "saved": true}   ← ইঞ্জিন যা *রাখল*, সেটাই ফেরত আসে
```

সংখ্যাগুলো **দুই দিকেই** clamp হয় (ঢোকার সময় ও পড়ার সময়), তাই হাতে ডেটাবেসে
লেখা `999`-ও বাজেট কোডে পৌঁছায় না:

| কী | সীমা | মানে |
|---|---|---|
| `thresholdPercent` | ১০–৯০ | উইন্ডোর কত % ভরে গেলে কম্প্যাকশন শুরু |
| `summaryTokens` | ১০০–৪,০০০ | চাওয়া সারসংক্ষেপের ডিফল্ট আকার |
| `tempKeepSecs` | ০–৩,৬০০ | temp সাব-এজেন্ট শেষ হওয়ার পর কতক্ষণ থাকবে |
| `standbyTtlSecs` | ৩০০–২৫,৯২,০০০ | standby এজেন্ট কতদিন বাঁচবে |

**প্যানেলের সুইচ:** প্যানেল এখন নিজেই চালু/বন্ধ করতে পারে। বন্ধ থাকলে ফাঁকা চেকলিস্ট
দেখায় না — এক প্যারাগ্রাফে বলে দেয় "বন্ধ" और एकটাই বোতাম দেয়। বোতাম চাপলে
`ctx.settings` পাঠায়, আর **ইঞ্জিনের উত্তরটাই** দেখায় (ইচ্ছা নয়) — তাই কোনো লেখা
আটকালে বা clamp হলে স্ক্রিনে সত্যিটাই থাকে।

চালু হলে যা ঘটে (প্রতি রিকোয়েস্টে):
1. ইঞ্জিন ফ্ল্যাগটা পড়ে (একবার)।
2. প্রম্পটের অংশগুলো + ট্রান্সক্রিপ্ট ইনডেক্স হয় (নোড তৈরি/হালনাগাদ)।
3. বাজেট হিসাব হয় — লকড অংশ বাদ দিয়ে বাকিটা "selectable"।
4. প্রয়োজনে সবচেয়ে কম-দামি আইটেম বাইরে যায় (কারণ লগে লেখা হয়)।
5. প্রম্পটে যোগ হয়: নিয়ম + চেকলিস্ট (+ দরকার হলে resume ব্লক)।
6. `ctx` টুল তালিকায় আসে (৪৪৮ টোকেন)।

বন্ধ থাকলে: টুল তালিকায় আসে না, প্রম্পট অপরিবর্তিত, খরচ শূন্য (একটা atomic load)।

## ৩. মডেল কী কী করতে পারে (`ctx`)

| action | কাজ | উদাহরণ |
|---|---|---|
| `view` | চেকলিস্ট দেখা; `path` দিয়ে এক আইটেম, `since_rev` দিয়ে শুধু পরিবর্তন | `{"action":"view"}` |
| `set` | ১২টা পর্যন্ত পরিবর্তন একসাথে: include / exclude / note_only / pin / unpin / move / tag | `{"action":"set","ops":[{"id":"turn/t12","action":"exclude"}],"expect_rev":41}` |
| `category` | নিজের ক্যাটাগরি বানানো (`cat/…`), টোকেন ক্যাপ দেওয়া, মুছে ফেলা | `{"action":"category","id":"cat/c1","title":"Migrations","max_tokens":3000}` |
| `summarize` | কয়েকটা আইটেমের বদলে একটা সামারি; উৎসগুলো স্টোরে থেকে যায় | `{"action":"summarize","ids":["turn/t3","turn/t4"],"focus":"গৃহীত সিদ্ধান্ত"}` |
| `recall` | বাইরে থাকা আইটেম ফেরানো (turn/result/ফাইল/নোট) | `{"action":"recall","id":"res/R7","keep":true}` |
| `note` | নিজের নোটবুক: যা গুরুত্বপূর্ণ, নিজের ভাষায় | `{"action":"note","title":"বিল্ড কমান্ড","text":"gradlew assembleRelease"}` |
| `strategy` | বড় কাজের প্ল্যান + পরের ধাপ | `{"action":"strategy","text":"১. পড়া ২. প্যাচ ৩. টেস্ট","step":"প্যাচ"}` |
| `prompt` | প্রম্পটের অংশ লোড/আনলোড (`sys/core` কখনো আনলোড হয় না) | `{"action":"prompt","unload":["tools.mcp"]}` |

নিয়ম:
- **`expect_rev`** দিলে ছবিটা পুরোনো হলে কিছুই প্রয়োগ হয় না — মডেল আবার পড়ে নেয়।
- **`dry_run`** দিলে কী হবে বলে দেয়, কিছু বদলায় না ("এতে কত টোকেন লাগবে?").
- একই কলে ১০টা op একে অপরকে দেখতে পায় (exclude তারপর note_only — কাজ করে)।
- একটা লকড আইটেম ফেল করলে বাকিগুলো ফেল করে না; শুধু ওইটা কেন হলো না, সেটা বলে দেয়।

## ৪. বাজেট আর স্বয়ংক্রিয় ব্যবস্থা

```
selectable = window − output reserve − headroom − locked
used       = ভেতরে থাকা আইটেমগুলোর টোকেন
```

ধাপে ধাপে (প্রতিটা আগেরটার চেয়ে কড়া):

| ধাপ | কখন | কী হয় |
|---|---|---|
| `none` | used ≤ ৮৫% | যেমন আছে তেমনই |
| `warn_soft` | ৮৫%–১০০% | চেকলিস্টে সতর্কবার্তা, পাঠানো হয় |
| `compact` | > compact_at | সবচেয়ে কম-দামি আইটেম বাইরে (মডেলের pin বাদে) |
| `force` | > ১১৫% | মডেলের pin-ও যেতে পারে, লগে `forced` লেখা হয় |
| `starved` | লকড অংশই উইন্ডো ছাড়ায় | শুধু আইন + নতুন প্রশ্ন পাঠানো হয়, resume ব্লক দিয়ে |

"কম-দামি" মানে: টার্ন-রিসেন্সি (৪০ টার্ন ও ৬ ঘণ্টা half-life) + কতবার ব্যবহার হয়েছে
(`ln`) + ধরন (essential সবচেয়ে দামি, tool result সবচেয়ে সস্তা) − ক্যাটাগরি ক্যাপ ছাড়ালে জরিমানা।

## ৫. ডেটা কোথায় থাকে

সেশন ডেটাবেসে নতুন টেবিল (`ctx_*`), কিছু মুছে ফেলা হয় না, কিছু নাম বদলায় না:

`ctx_sessions` (rev, id কাউন্টার) · `ctx_nodes` (index) · `ctx_categories` ·
`ctx_notes` · `ctx_temp_summaries` · `ctx_strategy` · `ctx_action_log` (কে, কখন, কেন) ·
`ctx_meta` (ফ্ল্যাগ, স্কিমা ভার্সন)।

নিয়ম:
- প্রতিটা কেরি `session_key` দিয়ে বাঁধা — এক চ্যাট আরেক চ্যাটের ডেটা দেখতে পারে না।
- **id কখনো পুনর্ব্যবহার হয় না** — ডিলিট হলে সমাধি (tombstone) থাকে, তাই পুরোনো প্রম্পটের
  id ভুল করে অন্য আইটেম দেখাতে পারে না।
- `sys/core`, essential, note আর pin করা আইটেম GC কখনো ছোঁয় না।
